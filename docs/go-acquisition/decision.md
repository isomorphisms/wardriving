# Go acquisition decision and evidence

This is the completed Sun investigation for SUN-WIFI-GO-ACQUISITION-01.
It chooses the implementation path and leaves executable experiments and
bounded follow-up jobs. It is **not** a completed acquisition app or APK.

## Decision

1. Keep the production Go engine app-owned, entered through a small C ABI.
   Use the existing Android-NDK typed framework-class writer for native
   callbacks; use JNI only at that mechanical Android boundary. Engine state,
   history, ranking, deadlines and HTTP policy remain Go-owned.
2. Use Go `net/http` and `crypto/tls` for Wardriving-owned verification. Scope
   the pool to one Android Network generation. Supply a native network-specific
   resolver and per-socket binding adapter. Do not use default-network DNS.
3. Retain Shizuku for operations requiring shell authority, such as saved
   metadata, through a bounded, authenticated adapter. Do not make a shell-UID
   Go daemon own app-private history or normal internet probes. Do not start
   rish for every RSSI sample or HTTP request.
4. Keep the current awk scout as its diagnostic fallback. Parse/store BSSID
   observations before presentation grouping in the production Go engine.
5. Start with existing scan and connection evidence. New scans, HTTP checks
   and portal interaction are conditional work, not mandatory launch steps.

The app-owned library avoids a second long-lived process, IPC state and history
ownership across UIDs. Those are architectural cost differences, not measured
C67 savings. Shared-library startup/GC and the native bridge must pass the
first Earth job before engine rollout. Foreground preparation needs Android
lifecycle qualification; a Go goroutine does not grant background execution.

## Android callback and resolver contract

The typed framework writer can describe `ConnectivityManager.NetworkCallback`
and `WifiManager.ScanResultsCallback` subclasses with no-argument constructors
and native methods, following IB's existing source-shaped generator. In
production, mechanically emitted classes call a thin native adapter, which
queues bounded events to Go. Callbacks must not wait for HTTP or disk I/O.

The adapter mints a monotonically increasing generation on Network replacement
or material address/route/resolver/proxy/validation changes. A stale callback
cannot retire a newer generation. A same-network radio roam updates RSSI and
BSSID without inventing a new internet result; material link changes still
invalidate the applicable results. Choose and test the fingerprint explicitly.

The Go transport must receive a real handle from `Network.getNetworkHandle`,
resolve using that same Network, and bind sockets before connect with
`android_setsocknetwork`. Keep host/SNI/certificate identity tied to the
original URL even when connecting to an explicitly resolved address. Set no
implicit environment proxy. A required configured proxy or VPN path must be
represented and independently qualified rather than silently bypassed.

Verify Android certificate-store behavior explicitly. The inspected Go source
adds `/system/etc/security/cacerts` and `/data/misc/keychain/certs-added`; it
does not itself prove parity with the C67's active Conscrypt/APEX store or
application trust policy. Qualify the intended roots/update behavior on API34
without disabling TLS or substituting the loopback fixture CA.

For cancellation, use the Android API29+ asynchronous resolver boundary
(`android_res_nquery`/`android_res_nsend`, readiness FD,
`android_res_nresult`, `android_res_cancel`) behind a bounded owner. Result and
cancel are mutually exclusive terminal operations; `nresult` closes its FD.
Do not race cancellation against FD reuse or wrap an indefinitely blocked
getaddrinfo call in a goroutine and call it cancelled. Preserve resolver cache
defaults. DNS64/NAT64 address selection and Private DNS require actual tests.

Use existing Android resolver/parser primitives or a pinned maintained DNS
parser; writing a new unbounded packet parser is outside the decision. The
first Earth job must prove the exact result/FD/cancellation semantics before
this becomes a production resolver.

There is no authenticated remote channel to the physical C67 in this run. The
prepared read-only diagnostic queries identity/model/release/ABI and existing
Wi-Fi command surfaces only. It does not scan, associate, log in or probe the
internet. Even a successful command exit is labeled command completion, not
semantic feature acceptance.

## Protocol decisions

| Work | Decision and savings | Invalidating condition / limit |
| --- | --- | --- |
| Fixed launcher wait | Remove from future first-display path; expose existing cache immediately | Original scout remains untouched in this Sun branch |
| New full scan | Use platform cache first; try targeted channels only after exposed control is proved | Old channel/location may be wrong; expand on a bounded miss |
| DHCP | Observe platform lease confirmation and Rapid Commit; do not implement a competing DHCP client | Both peer/client feature support and current network state matter; no measured C67 savings |
| FILS/fast roaming | Conditional capability work only | Do not assume public AP or chipset support |
| DNS | Retain platform per-Network cache; no duplicate query solely for a green diagnostic | Network/configuration changes; no default-route fallback |
| TCP/TLS | Retain pool; bounded in-memory session cache when eligible | Loss/replacement resets live pool; TLS tickets do not retain internet verification |
| TLS early data | Defer | Go TCP HTTP transport has no general 0-RTT switch; QUIC work is not justified by current measurements |
| Portal detection | Reuse current system state; otherwise inspect first bounded HTTP response when needed | Redirect is possible portal evidence, not authorization proof |
| Returning session | Preserve legitimate Android identity/cookie state and test current access first | Session expiry/revocation/reboot can invalidate it |
| Promotional landing page | Do not wait after authorization and required reachability already work | Required login scripts/consent must finish; no automatic acceptance |
| Throughput/loss series | On-demand; retain useful request timings | Do not consume radio time before first useful internet |

Before approval, useful work includes history lookup, local ranking, cache
consumption and permitted metadata. A nearby unassociated AP cannot receive an
ordinary internet probe from a single client association. Preparation must
not quietly connect to it.

## State, history and direction

Production state is an app-private bounded journal with atomic snapshots and
explicit crash recovery, not SQLite by default. Store per-BSSID/security/band
observations, saved eligibility, observation age, outcomes, stage timings and
cooldowns. Retain SSID display grouping separately. Fixed-width shell output
can trim/lose SSID fidelity; prefer framework WifiSsid/ScanResult bytes where
available and record the provenance rather than inventing identity.

Cache a venue's recurring connection flow, not session nonce URLs or a claim
that every branch of a chain shares authorization. Bank/restaurant/vendor are
priors only. DHCP and DNS can work before authorization. An allowlisted portal
host is not an unrestricted-internet oracle.

Rank predicted time to useful access and uncertainty; use signal, failure
cooldowns, legitimate returning sessions, location and time as inputs. Keep
historical, predicted, current-visible and verified states separate.

Directional state uses independent timestamped observations of the same BSSID
and band. GNSS travel bearing is not phone orientation. One straight segment
supports an along-path trend, not a unique 2-D bearing. A historical useful
location is a separately labeled destination. No distance-to-AP from RSSI.
Confidence, uncertainty and actual movement tests are required before an arrow
is called qualified. This algorithm remains unimplemented in the Sun spike.

## Completion and next work

Follow `implementation-jobs.md`. The first implementation gate is the real
Android callback/resolver/socket transaction, not rewriting a UI or another
scanner. The original POSIX awk remains available throughout. No production
package ID/signer has been observed for Wardriving; establish identity and
installed-state compatibility before delivery. Never generate a fallback key.

Host tests and Android object/link checks are useful intermediate evidence.
No signed application, automatic joining, release, merge or physical acceptance
is claimed by this report.
